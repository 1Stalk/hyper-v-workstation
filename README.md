# Hyper-V GPU-PV Gaming Virtual Machine Cluster

Автоматизированная инфраструктура игровых виртуальных машин на базе технологии **Hyper-V GPU Partitioning (GPU-PV)** с оконным интерфейсом в стиле **VMware Workstation** и встроенной системой **аппаратного спуфинга и рандомизации железа (Anti-VM Detection)**.

---

## 1. Спецификация хостовой системы

- **Процессор**: Intel Xeon E5-2696 v3 (Haswell, 18 ядер / 36 потоков, 2.3–3.1 GHz, поддержка VT-x, VT-d, SSE4.2, POPCNT).
- **Оперативная память**: 64 ГБ DDR4 ECC.
- **Видеокарта**: NVIDIA GeForce GTX 1050 Ti (4096 МБ VRAM, драйвер 560.94 WDDM с поддержкой до 8 одновременных NVENC сессий).
- **Хостовая ОС**: Windows 11 Enterprise (25H2 Build 26200).
- **Гостевая ОС**: Windows 11 Pro (25H2, образ `install.wim` Индекс 3).

---

## 2. Архитектура решения

### Выделение ресурсов на одну виртуальную машину:
- **vCPU**: 4 виртуальных ядра (позволяет запустить до 5 VM, оставив 16 ядер хосту).
- **RAM**: 8 ГБ статической оперативной памяти.
- **VRAM**: **Ровно 1 ГБ (1024 МБ)**. Нормализованное значение GPU-PV: `250 000 000` из 1 млрд (25% от 4 ГБ).
- **Жёсткий диск**: **150 ГБ** (разностный VHDX на базе единого эталонного мастер-диска `Gaming-Base.vhdx`).

### Полный отказ от AntiOS и собственная система Anti-VM Spoofing:
- **AntiOS полностью удалён**: старые утилиты AntiOS ломали сетевой стек WinNAT, сбрасывали статические IP и повреждали службы Windows.
- **Собственный спуфинг железа (Host-HyperV-Randomize)**:
  - **SMBIOS / DMI**: Серийный номер BIOS (`BIOSSerialNumber`), материнской платы (`BaseBoardSerialNumber`), шасси (`ChassisSerialNumber`), инвентарный номер (`ChassisAssetTag`), и системный UUID (`BIOSGUID`) прошиваются напрямую в виртуальный UEFI через Hyper-V WMI v2 (`root\virtualization\v2`).
  - **SCSI Disk Identifier**: Аппаратная сигнатура диска сбрасывается утилитой `Set-VHD -ResetDiskIdentifier`.
  - **MAC-адрес**: Генерируется из пулов реальных производителей (Intel, Realtek, Dell) с включенным `-MacAddressSpoofing On`.
  - **GPU Partition Adapter**: Переинициализируется с выделением нового GUID раздела и сохранением квоты 1 ГБ VRAM.
  - **Внутренние Windows GUID**: Автоматическая рандомизация `MachineGuid` (Crypto), `HardwareProfileGuid`, `ProductId`, `BuildGuid`, `InstallDate`, телеметрии `SQMClient\MachineId`.
  - **VolumeID**: Серийный номер тома NTFS `C:` рандомизируется утилитой Sysinternals `Volumeid64.exe`.
  - **Сетевая стабильность (Watchdog)**: Автоматическая служба гарантирует сохранение статического IP (`192.168.100.11`/`12`), шлюза (`192.168.100.1`) и DNS даже при смене MAC-адреса.

## 4. Быстрый запуск

1. Запустите консоль управления:
   - Двойным кликом по `Start-HyperV-Workstation.cmd`.
2. Выберите виртуальную машину `Gaming-VM1` или `Gaming-VM2` в списке слева.
3. Нажмите **[▶ Запустить VM]**.
4. Нажмите **[🖥️ Открыть окно (Moonlight)]** — откроется отдельное окно с разрешением 1024x768 @ 60 FPS.
5. Для рандомизации аппаратного профиля выключенной машины нажмите **[🎲 Спуфинг HWID]**.
6. Для создания новых машин (VM3..VM5) нажмите кнопку **[➕ Клонировать новую VM]** — машина будет создана за 20 секунд с уникальным IP, рандомизированным SMBIOS, уникальным MAC и диском 150 ГБ.
